## 二、本周任务（就这一个）

### 第 1 步：先跑一次，拿到 v0 的基线数据（10 分钟）

双击 `run.cmd`，把 `v0` 那一行抄进 xlsx。

### 第 2 步：实现 `gemm_v1`（30 分钟）

打开 `gemm.c`，找到 `gemm_v1` 那个函数。文件里的注释已经写了骨架，**先自己写一遍再看注释**。

写完再跑一次。看到 `[正确]` 且 GFLOPS 明显更高，就成了。

### 第 3 步：测四个规模（20 分钟）

```
run.cmd 256  5
run.cmd 512  3
run.cmd 1024 3
run.cmd 2048 1
```

每个规模记两行（v0 / v1）。

### 第 4 步：回答一个问题（写下来，20 分钟）

> **v1 比 v0 快了几倍？快在哪？**

提示：算一下 v0 的内层循环里，`B[k*N+j]` 每加一次 k，地址跳多少个字节。
再对比 v1 的内层 `B[k*N+j]` 每加一次 j，跳多少字节。
一个 cache line 是 64 字节，装得下几个 float？

**这个问题就是面试要问你的第一个问题。** 答不上来，数据再漂亮也没用。

## 二·五、你的机器（算理论峰值用）

| 项 | 值 |
|---|---|
| **CPU** | Intel Core **i7-12700H**：6 个 P 核 + 8 个 E 核 = 14 核 20 线程 |
| 指令集 | **支持 AVX2 + FMA，不支持 AVX-512**（12 代消费级被禁用） |
| **GPU** | **NVIDIA GeForce RTX 3050 Laptop** ← v5 CUDA 可以直接在本机做，不用租云 |
| 主频 | 基频 2.688 GHz（P 核睿频 ~4.7，E 核 ~3.5） |

**理论单精度峰值**（AVX2 FMA = 每核每周期 16 FLOPs）：

```
P 核：  6 核 × 4.7 GHz × 16 = 451 GFLOPS
E 核：  8 核 × 3.5 GHz × 16 = 448 GFLOPS
                         合计 ≈ 900 GFLOPS
```

笔记本散热撑不住全核睿频，**实际可持续大概 400–600 GFLOPS**。

> ### ★ 你的 v0 基线是 0.856 GFLOPS = 峰值的 0.1%
>
> **所以这条阶梯有将近 1000 倍的路可以走。** 这既是机会，也是提醒——
> 你现在的瓶颈离"算术能力"还差得远，**完全卡在访存上**。

**一个已经能看出来的现象**（你第一次跑就会看到）：

| N | v0 GFLOPS | 为什么 |
|---|---|---|
| 256 | **3.86** | 256×256×4B = 256KB，装得进 L2 |
| 1024 | **0.86** | 1024×1024×4B = 4MB，溢出到 L3/DRAM |

**同样的代码，只因为数据装不进 cache，慢了 4.5 倍。** 这就是这个项目要讲的故事。

## 三、数据填哪儿

`E:\虚拟C盘\CSP冲刺日程表.xlsx` → 「项目·GEMM」页 → 性能数据表。

**只填 `N` 和 `耗时(ms)` 两列，`GFLOPS` 会自动算出来**（公式已经内置）。

「观察到的瓶颈」那一列，**别写"我猜是访存"**。

| ❌ | ✅ |
|---|---|
| 我猜是访存瓶颈 | `perf stat` 显示 LLC-load-misses 是 12.3M，L1-dcache-load-misses 是 89M |
| 应该是 cache 没命中 | 用 `perf stat -e cache-misses,cache-references ./gemm 1024` 得到命中率 62% |

Windows 上没有 `perf`，可以先用：
- **任务管理器 → 性能**：看 CPU 占用和内存带宽有没有跑满
- **Intel VTune**（免费，有 Windows 版）
- 或者**临时用 WSL / 云服务器上的 Linux** 跑一次 `perf` 拿准确数字

## 五、三条纪律（贴在显示器上）

**纪律一：Day 1 就开始记数据。**
不要等"做完了再整理"。每跑一次就填一行。**这张表就是你面试的全部说服力。**

**纪律二：每一版都写一句「瓶颈在哪」，用工具测，不凭感觉。**
「我猜是访存瓶颈」和「perf 显示 LLC miss rate 是 12%」是两个量级的回答。

**纪律三：正确性优先于性能。**
`gemm.c` 里内置了自检（随机抽查 64 个格子跟直接点积对比）。
**每一版先看到 `[正确]`，再看 GFLOPS。漂亮数据但结果错，比慢更糟。**

## 六、你的两个已知弱点，在这个项目里会被放大

| 弱点 | 后果 | 对策（已经写进代码/流程了） |
|---|---|---|
| **不先估复杂度就动手** | 优化方向错了——你优化了 5%，真正瓶颈在别处 | **先算理论峰值**：`核数 × 主频(GHz) × 每周期浮点操作数`。每次优化前问"我现在是峰值的百分之几" |
